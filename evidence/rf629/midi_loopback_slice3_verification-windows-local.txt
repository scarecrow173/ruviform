## Real-device lane (test-midi-real-device) — FAILED, root cause outside slice scope

`mise run test-midi-real-device` — exit 101.

- `ruviform-midi-device --lib` unit test
  `os::windows_output::tests::real_device_send_smoke` FAILED:
  `winmm midiOutOpen failed` at
  `crates/ruviform-midi-device/src/os/windows_output.rs:513`.
- Root cause (measured, auxiliary PowerShell P/Invoke):
  `midiOutOpen(CALLBACK_FUNCTION|MIDI_IO_STATUS=0x30040)` on
  "Microsoft GS Wavetable Synth" returns `MMSYSERR_INVALFLAG` (10);
  `CALLBACK_FUNCTION` alone returns 0. The #658 backend
  unconditionally passes `MIDI_IO_STATUS` (needed for `MM_MOM_DONE`
  SysEx completion), so every real-device output open fails on this
  host. Latent since 2nd slice — that slice recorded the lane as
  NotRun and never executed it.
- `src/os/windows_output.rs` is outside this slice's declared edit
  scope; escalated to coordinator (ask msg_8221753a9939, pending at
  evidence time).
- Because cargo stops at the first failing test target, the lane did
  not reach `tests/loopback.rs` / `tests/output_ports.rs` /
  `tests/ports.rs` integration binaries on this run.
