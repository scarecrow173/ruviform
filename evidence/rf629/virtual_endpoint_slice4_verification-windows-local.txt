## What the Pass results actually prove (OS-L1 only)

- The verifier compiles under `--features real-device` with
  `-D warnings`, is collected only when the feature is on, uses
  exclusively production `DeviceEnumerator`/`Device`/stream traits
  (no Win32 FFI, no cpal-direct, no test-only endpoint logic), and
  fails closed to `NotRun — NOT_PROVISIONED` without a pair.
- The oracle is self-contained in the test file (deterministic
  `signal_sample` generator + marker/level/Goertzel-tone checks) —
  no `ruviform-audio-test` dev-dependency was added (coordinator
  decision (A)); the #628 `PcmFixture`/`RunMetadata` handoff is
  documented for a later slice.
- `endpoint_probe` prints the pair-candidate table using the same
  name-stem rule as the verifier, plus best-effort driver-signature
  (`Win32_PnPSignedDriver` + `Get-AuthenticodeSignature` on staged
  catalogs) and HKCU microphone-permission observations; every
  optional-query failure degrades to a `NotRun` note with exit 0.
- Cleanup is recorded: the probe creates no persistent state.

## Explicitly NOT proven here

- `virtual-os-endpoint` evidence — no virtual pair provisioned;
  nothing in this slice claims it.
- EXT-L3 provider/driver integration — driver signature output is
  a best-effort observation record, not signed-driver proof for a
  virtual endpoint.
- Real round-trip signal correctness — the oracle path is
  implemented but has never seen provisioned hardware; tolerances
  (level band, tone share, marker interval) are provisional pending
